## P0: 基盤 ✅

UIに依存しない集計ロジックを `src/visualization/` に集約し、薄いUI層から利用する土台を作る。

### スコープ（やること）
- 予測結果CSV（`outputs/test_predictions.csv`）の読み込みと必須列の検証
- `@st.cache_data` による読み込み・集計のキャッシュ
- 行政区単位・駅単位の集計テーブル生成（件数・予測/実測価格の平均と中央値・MAPE・Median APE）
- 入力CSVパスの設定切り替え（環境変数 `BI_PREDICTIONS_PATH`）
- 集計・フィルタ・KPIの純粋関数化とユニットテスト

### 対応要件
- **M-1**: データ読み込み・前処理

### 成果物
- `src/visualization/aggregate.py`（集計・フィルタ・KPI）
- `src/visualization/master.py`（市区町村コード↔名称マスタ）
- `src/visualization/format.py`（金額の「億・万」整形）
- `configs/tokyo_municipality_master.csv`
- `tests/test_aggregate.py` / `test_master.py` / `test_format.py`

### 改善作業で強化した点（P0-1〜P0-3）
- 残差の符号を `error_yen`（= 予測 − 実測）に一本化
- 必須列チェックをダッシュボードが参照する列まで拡張（読込時に不足を検知）
- 入力CSVパスを `BI_PREDICTIONS_PATH` で切り替え可能化

## P1: BIグラフ ✅

予測結果を非エンジニアでも直感的に把握できるグラフ群とフィルタを提供する。

### スコープ（やること）
- KPIサマリ（ヘッダ指標カード）
- Plotlyによる多面的なグラフ
- サイドバーフィルタ（全グラフ・KPIに連動）

### 含むグラフ（M-3）
| グラフ | 内容 | 状態 |
|---|---|---|
| 予測 vs 実測 散布図 | y=x基準線つき・色=APE | ✅ |
| 誤差分布ヒストグラム | APE / 残差(error_yen) を切替 | ✅ |
| 価格帯別 件数・精度 | 価格帯ごとの件数＋平均APE | ✅ |
| 行政区別 ランキング | 平均予測価格／平均APE（Top20） | ✅ |
| 駅別 ランキング | 同上（駅単位） | ✅ |
| 特徴量との関係 | 面積／築年数 × 予測価格（X軸selectbox・色=もう一方） | ✅ |

### フィルタ（M-6）
行政区（市区町村名で選択）・最寄駅（行政区に連動）・物件種類・価格帯（金額順）・面積レンジ・築年数レンジ・山手線内側。すべてグラフ・KPIに連動。✅

### KPIサマリ（M-2）
件数・R²(log)・MAE・RMSE・MAPE・Median APE をカード表示。✅

### 対応要件
- **M-2**（KPI）・**M-3**（グラフ）・**M-6**（フィルタ）

### 成果物
- `app/pages/1_BIダッシュボード.py`

### 改善作業で強化した点（P1）
- ランキング集計を `@st.cache_data` 付きヘルパー経由に変更（再計算を削減）
- 特徴量タブにX軸切り替え（面積／築年数）を追加
- 金額の「億・万」表記（散布図ホバー・ランキング棒ラベル）
- KPI各カードに指標定義のツールチップ追加
- 散布図サンプリング表示時の注記追加
- ランキング棒に平均APEの色分けを適用

> 緯度経度欠損件数の明示（M-1/§3.2）は地図表示が前提のため P2 で対応済。

## P2: 地図（駅単位）✅

駅単位の集計値を地図上のマーカーで可視化し、クリックで詳細をポップアップ表示する。

### スコープ（実施内容）
- folium ＋ streamlit-folium を依存追加
- `最寄駅：緯度／経度` に CircleMarker を配置（色＝指標、半径＝件数の平方根スケール）
- マーカークリックで件数・平均/中央 予測価格・実測価格・APE・代表種類/価格帯をポップアップ
- 緯度経度欠損行は地図から除外し、除外件数をUIに明示
- 表示指標の切替（平均予測価格／平均実測価格／平均APE）

### 対応要件
- **M-4(駅)**: 地図可視化（駅単位）
- **M-5(駅)**: クリック時ポップアップ

### 成果物
- `app/pages/2_地図.py`（粒度トグルで駅／行政区を切替、本フェーズは駅側を実装）
- `src/visualization/aggregate.py` の `station_map_summary`（代表種類・価格帯付き集計）

## P3: 地図（行政区）✅

行政区（市区町村コード）単位でGeoJSONによるコロプレス（塗り分け）地図を描画する。

### スコープ（実施内容）
- 東京都市区町村のGeoJSON（国土数値情報 N03）を `configs/tokyo_municipalities.geojson` に配置
- `市区町村コード` をキーにGeoJSONと集計を結合してコロプレス描画
- 粒度トグル（駅／行政区）。初期表示は行政区単位
- 区画クリックで市区町村名・件数・予測/実測価格・APE・代表種類/価格帯をポップアップ

### 対応要件
- **M-4(区)**: 地図可視化（行政区単位）
- **M-5(区)**: クリック時ポップアップ

### 成果物
- `src/visualization/geo.py`（行政区／駅／物件 3種の GeoJSON ローダ）
- `src/visualization/aggregate.py` の `ward_map_summary`
- `app/pages/2_地図.py` に行政区ブランチを統合
- `configs/tokyo_municipalities.geojson`

## P6: トップページ＋評価指標一覧 ⬜

`home.py` 本体（現在は真っ白）を仕上げ、各ページへの導線と評価指標の一覧を提供する。

### スコープ（やること）
- **トップページ実装**: `app/home.py` にランディングUIを実装
  - プロジェクト概要・データソース・モデルの説明
  - 各ページ（BIダッシュボード／地図）への導線
  - 現行モデルの主要評価指標サマリ（R²log・MAE・RMSE・MAPE・Median APE・PE10 等）
- **評価指標一覧の追加**: 各指標の定義・計算式・解釈・閾値の一覧をアプリ内で参照可能に
  - 既存の `docs/../modeling/evaluation_metrics.md` を Streamlit ページ化、もしくはトップページ内のセクションとして実装
  - 価格帯別の指標表示（業界基準との比較）

### 対応要件
- 仕様書では明示されていない追加要件（F-1 のうち UI 統合部分に近い）

### 成果物（予定）
- `app/home.py`（実装）
- `app/pages/N_評価指標一覧.py`（新規ページの場合）または `app/home.py` 内セクション

### 主なリスク・検討事項
- 評価指標を「静的な定義」だけ載せるのか、「現行モデルの数値」も含めるのか
- 数値を載せる場合の更新運用（再学習のたびに最新化するか、ベースライン固定か）
- トップページと既存ページの役割分担（重複表示を避ける）
