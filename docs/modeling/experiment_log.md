# モデル実験管理シート

東京都不動産価格予測モデルの学習・評価の実験ログ。新しい仮説や改善を試したら、
表に1行追加するとともに、後段の「個別実験詳細」にエントリを書き起こす運用とする。

- 評価指標の定義: [evaluation_metrics.md](evaluation_metrics.md)
- 学習スクリプト: `src/modeling/train.py`
- 設定ファイル: `configs/model_params.yaml`
- 学習ログ: `logs/train.log`

---

## 1. 運用ルール

### エントリ追加の手順
1. 学習を実行する前に、本シートの「個別実験詳細」に新規エントリを起こし、**仮説・狙い・変更点**を先に書く。
2. 学習完了後、`logs/train.log` から該当ランの最終スコアをコピーして埋める。
3. サマリ表（§2）にも1行追加する（ID, 日時, 仮説, 主要スコア, ベストID 比較）。
4. 観察と次のアクションは**後日でも構わない**が、なるべく当日のうちに書く。

### ベストモデルの扱い
- サマリ表で「Best?」列に印を付けたエントリが現行ベスト。
- ベスト更新時は、旧ベストの「Best?」をクリアし、新ベストへ移す。
- `models/best_params.yaml` を上書きしたかどうかも明記する。

### スコアの優先順位
- **R² log / RMSE log**: モデルそのものの素性（log空間での適合）
- **MAE yen / RMSE yen**: 円スケール（外れ値の影響を受けやすい）
- **MAPE / Median APE**: 比率誤差。Median APEは外れに頑健、MAPEは平均で歪みを含む

どれか1つだけでは判定しない。特に「MAEだけ良くなった」ようなケースは内部介入で生じやすいので、複数指標で総合判断する。

### 評価データの一貫性
- **test セットへの介入（クリップ・除外・代替値）は禁止**。test は常に素の actual で評価する。
- 学習側（train/val）の介入は明記する。

### EXP-005: 学習側のみクリップ（test は素のまま）

| 項目 | 値 |
|---|---|

| データ分割 | train=23,795 / val=7,932 / test=7,932 |
| 介入 | `main()` の `train_test_split` 直後で `y_train`・`y_val` のみ ln(3e8) で `clip(upper=…)`。`y_test` は素のまま評価。クリップ実件数: train=256件 / val=83件（test は無修正） |
| 仮説 | EXP-004 で見えた「外れ値の影響を抑える」効果のうち、学習側介入による純粋な改善幅を把握する。test 側の見かけ上の縮小を排除した、honest な数値を得る |

| Optuna best RMSE_log | 0.2094 |

**スコア（test、素の actual で評価）**
| 指標 | 値 | EXP-001 比 | EXP-004 比 |
|---|---:|---:|---:|
| R² (log) | 0.925 | −0.003 | −0.003 |
| RMSE (log) | 0.219 | +1.4% | +3.3% |
| MAE | 9,925,205 円 | **+8.8%** | +21.5% |
| RMSE | 28,978,844 円 | **+28.9%** | +100.5% |
| MAPE | 15.874 % | +1.1% | +2.3% |

**観察**
- **全指標でベースライン（EXP-001）を下回り、仮説は反証された**。特に RMSE は +28.9% と大幅悪化
- 原因: 学習データから3億超を実質除外した結果、モデルが高額帯の予測能力を失い、test に残っている高額物件（97件＋）への予測が大きく外れて、絶対誤差の総量が増えた
- EXP-004 の見せかけ良かった数字は「test の actual も上限頭打ち」によるアーティファクトであったことが裏付けられた（クリップした分の真の誤差が EXP-005 で表面化）
- 高額物件は希少だが、モデルにとって「学習データの一部として残しておく方が有利」であることを示唆
- R² log・RMSE log・MAPE・Median APE は微小な悪化に留まり、log 空間の素性は概ね維持

**次のアクション**
- 単純な winsorize/drop は逆効果と判明。**EXP-001 がベスト維持**
- 高額物件への耐性を上げつつ学習サンプルを失わない方向へ転換:
  - EXP-006: Huber 損失（外れ値感度を下げる）
  - EXP-007: サンプル重み付け（高額物件の影響だけ下げる、サンプルは残す）
- もしくはクリップ閾値を緩める（例: 5億・10億）案も検討（除外件数を最小限に）

### EXP-006: 価格帯均等化サンプル重み付け

| 項目 | 内容 |
|---|---|
| 日時 | 2026-06-01 22:33:33 |
| データ分割 | train=23,795 / val=7,932 / test=7,932 |
| 介入 | `compute_band_uniform_weights()` で `actual_price_band` 5帯の合計重みを均等化（mean=1.0、上限 cap=10倍）。`train`/`val` のみ `sample_weight` として LightGBM に渡し、`test` は重みなしで評価 |
| 仮説 | 件数の少ない高額帯（3億~ で 1.2%）を up-weight することで、学習の発言力を確保し、test に残る高額物件への絶対誤差（特に RMSE）を改善できる。EXP-005 で「サンプルを消す」が逆効果と確認済 → 反対方向（残しつつ重みを上げる） |
| 紐PROP | PROP-002 |
| 主な best_params | n_estimators=1129, lr=0.1326, num_leaves=154, max_depth=12, min_child_samples=86, subsample=0.786, colsample_bytree=0.655, reg_alpha=0.00506, reg_lambda=0.0225 |
| Optuna best RMSE_log | 0.2216 |

**実際の重み分布（ログ出力）**
- train: min=0.531, mean=1.000, max=11.018
- val: min=0.537, mean=1.000, max=11.054

**スコア（test、素の actual、重みなしで評価）**
| 指標 | 値 | EXP-001 比 | EXP-005 比 |
|---|---:|---:|---:|
| R² (log) | 0.922 | −0.006 | −0.003 |
| RMSE (log) | 0.224 | +3.7% | +2.3% |
| MAE | 9,493,540 円 | **+4.1%** | −4.3% |
| RMSE | 21,674,915 円 | −3.6% | **−25.2%** |
| MAPE | 16.443 % | +4.7% | +3.6% |
| Median APE | 11.157 % | +5.9% | +4.0% |

**観察**
- **採用条件未達**: PROP-002 の評価基準（MAE と RMSE がともに EXP-001 比 ≥5% 改善、Median APE ≤ 11%）を満たさず。
  - MAE は +4.1% **悪化**
  - RMSE は −3.6% 改善するも閾値 5% 未満
  - Median APE 11.157% で 11% を**上回る**
- 一方で EXP-005（クリップ）と比べると RMSE が −25.2% と大幅改善: 「サンプルを消す」より「重みで残す」方が高額帯の予測精度を保つことが裏付けられた
- 高額帯（3億~）を強く up-weight した結果、モデルが全体的に高額側へ引っ張られ、低・中額帯の精度（MAPE/Median APE）が悪化
- 価格帯均等化（=希少帯への大幅 up-weight）は強すぎる介入。重みコントロールの方向性は妥当だが、配分が偏った可能性

**次のアクション**
- PROP-002 は本構成では**不採用判定**。重みコントロール自体は方向性として有望なので、配分を調整して再試行する候補:
  - cap をより小さく（例: 3〜5倍）し、高額帯への偏りを緩める
  - 連続的な重み（`price^α`、`α` を小さめに）で滑らかにする
  - 低額帯のみ up-weight、高額帯はそのまま（非対称重み）
- ベストは引き続き EXP-001
- 実験案管理表（[experiment_proposals.md](experiment_proposals.md)）の PROP-002 状態更新と、後続案の起票は別途検討

### EXP-007: クリップ閾値の緩和（5億）

| 項目 | 内容 |
|---|---|
| 日時 | 2026-06-02 07:07:58 |
| データ分割 | train=23,795 / val=7,932 / test=7,932 |
| 介入 | `_TRAIN_PRICE_CAP_YEN = 5e8`（EXP-005 の3億から緩和）。`main()` の `train_test_split` 直後で `y_train`/`y_val` のみ `clip(upper=ln(5e8))`。`y_test` は素のまま評価。実クリップ件数: train=74件 / val=31件 |
| 仮説 | EXP-005 の3億は厳しすぎた（train 256件クリップ）。閾値を5億に緩めれば学習データ消失を最小化（74件、約 0.31%）しつつ外れ値の影響を一部抑えられる |
| 紐PROP | PROP-003 |
| 主な best_params | n_estimators=1185, lr=0.0616, num_leaves=230, max_depth=9, min_child_samples=49, subsample=0.825, colsample_bytree=0.617, reg_alpha=1.059, reg_lambda=0.063 |
| Optuna best RMSE_log | 0.2091 |

**スコア（test、素の actual で評価）**
| 指標 | 値 | EXP-001 比 | EXP-005 比 |
|---|---:|---:|---:|
| R² (log) | 0.928 | ±0 | +0.003 |
| RMSE (log) | 0.215 | −0.5% | −1.8% |
| MAE | 9,244,340 円 | **+1.3%** | −6.9% |
| RMSE | 23,250,027 円 | **+3.4%** | **−19.8%** |
| MAPE | 15.718 % | +0.1% | −1.0% |
| Median APE | 10.744 % | +1.9% | +0.1% |

**観察**
- **採用条件未達**: PROP-003 の評価基準「EXP-001 を下回らない」に対し、MAE +1.3% / RMSE +3.4% でわずかに下回る
- ただし R² log と RMSE log は EXP-001 と実質同等。**log 空間の学習精度はベースラインを維持**しつつ、円スケールの test 評価のみが微悪化する形（高額帯の予測能力低下が原因と推測）
- EXP-005 と比べると劇的に改善: MAE −6.9%、RMSE −19.8%。クリップ件数を 256→74 に減らしたことで、高額帯の予測能力損失が大幅に緩和されたことが確認できた
- 「クリップの度合いと test スコアの関係」: 3億（256件）→悪化大、5億（74件）→微悪化、10億（推定6件）→ ほぼ差なしと推測。**閾値を緩めれば緩めるほど EXP-001 に漸近するが超えない**構造が見えた

**次のアクション**
- 10億クリップ（EXP-008）を試す価値は薄い（5億で既にベースライン下回り、件数をさらに減らしてもベースラインに近づくだけで超えられない）
- PROP-003 の方向性そのもの（学習サンプルを部分的に消す）は天井が低いと判断
- 次は **PROP-001（Huber 損失）** など「サンプルを残しつつ損失関数で対処」する方向を優先
- ベストは引き続き EXP-001

## 5. 今後の実験アイデア（バックログ）

順序は優先順位の目安。実施したらここから消して個別エントリへ移す。

1. **EXP-006**: Huber 損失（外れ値感度を下げつつ高額物件は学習に残す）
2. **EXP-007**: サンプル重み付け（高額物件の重みのみ下げ、サンプルは残す）
3. **EXP-008**: クリップ閾値を緩めて再試行（例: 5億・10億）。除外件数を最小化して winsorize の効果を再評価
4. **EXP-009**: 低額帯（~2000万）の特徴量強化（築年×構造、駅遠×面積、用途地域の細分）
5. **EXP-010**: 低額帯向け予測の下限制約（実装妥当性の検討）
6. **EXP-011**: 2分割アンサンブル（低額専用モデル + 中〜高メインモデル）

> EXP-005 で「学習側だけクリップ」も逆効果と判明したため、当面は **サンプルを残しつつ損失関数や重みで対処する方向**（EXP-006/007）を優先する。
