# 評価指標ガイド

東京都の不動産価格予測モデルで用いる**評価指標の意味と読み方**をまとめる。
対象となる指標は `src/modeling/train.py` の `evaluate_regression()` が返す 6 種類。

## 前提: 2つのスケールで評価する

目的変数 `取引価格（総額）` は歪度が大きいため、学習時に**対数変換**している
（`y = log(取引価格)`）。そのため評価も 2 つのスケールで行う。

| スケール | 意味 | 対象指標 |
|---|---|---|
| **log スケール** | モデルが実際に学習・予測している空間。相対誤差の評価に向く | `r2_log`, `rmse_log` |
| **円（yen）スケール** | `np.exp()` で元の金額に戻した、人間が直感的に解釈できる空間 | `mae_yen`, `rmse_yen`, `mape`, `median_ape` |

```python
# train.py の評価ロジック（抜粋）
y_true_yen = np.exp(y_true_log)   # log → 円スケールへ復元
y_pred_yen = np.exp(y_pred_log)
ape = np.abs(y_true_yen - y_pred_yen) / y_true_yen * 100  # 絶対パーセント誤差
```

---

## 1. `r2_log` — 決定係数 (R², logスケール)

- **定義**: $R^2 = 1 - \dfrac{\sum (y_i - \hat{y}_i)^2}{\sum (y_i - \bar{y})^2}$ （logスケールで計算）
- **意味**: 目的変数のばらつきのうち、モデルが説明できた割合。
- **範囲 / 良し悪し**: 1.0 が完全予測、0.0 は「常に平均値で予測」と同等、負値はそれ以下。**1に近いほど良い**。
- **注意点**: 単位を持たずモデル間比較に便利だが、これ単体では誤差の大きさ（円）が分からない。

---

## 2. `rmse_log` — 二乗平均平方根誤差 (RMSE, logスケール)

- **定義**: $\text{RMSE} = \sqrt{\dfrac{1}{n}\sum (y_i - \hat{y}_i)^2}$ （logスケール）
- **意味**: logスケールでの誤差の標準的な大きさ。**小さいほど良い**。
- **読み方のコツ**: logスケールの誤差は近似的に**相対誤差**に対応する。
  $e^{\text{rmse\_log}} - 1$ がおおよその割合誤差。
  例: `rmse_log = 0.30` → $e^{0.30}-1 \approx 0.35$ なので「概ね ±35% 程度の誤差感」。
- **注意点**: 二乗するため大きな誤差（外れ値）の影響を強く受ける。

---

## 3. `mae_yen` — 平均絶対誤差 (MAE, 円スケール)

- **定義**: $\text{MAE} = \dfrac{1}{n}\sum |y_i - \hat{y}_i|$ （円）
- **意味**: 予測が平均して何円ずれているか。**小さいほど良い**。
- **長所**: 単位が「円」で最も直感的。外れ値に対して RMSE より頑健。
- **注意点**: 高額物件と低額物件の誤差を同じ「円」で合算するため、**高額帯に引っ張られやすい**。

---

## 4. `rmse_yen` — 二乗平均平方根誤差 (RMSE, 円スケール)

- **定義**: $\text{RMSE} = \sqrt{\dfrac{1}{n}\sum (y_i - \hat{y}_i)^2}$ （円）
- **意味**: 円スケールでの誤差の標準的な大きさ。**小さいほど良い**。
- **長所**: 大きな外れ予測に強いペナルティを与えるため、**致命的な大ハズレ**の検知に向く。
- **読み方**: `rmse_yen > mae_yen` の差が大きいほど、誤差のばらつき（大ハズレの存在）が大きい。

---

## 5. `mape` — 平均絶対パーセント誤差 (Mean Absolute Percentage Error)

- **定義**: $\text{MAPE} = \dfrac{1}{n}\sum \dfrac{|y_i - \hat{y}_i|}{y_i}\times 100\ (\%)$
- **意味**: 正解額に対して平均で何%ずれているか。**小さいほど良い**。
- **長所**: スケールに依存しない相対指標。高額・低額物件を公平に評価できる。
- **注意点**: 正解値 $y_i$ が小さい（安い）物件で値が極端に大きくなりやすく、**少数の安価物件に大きく振られる**。

---

## 6. `median_ape` — 中央絶対パーセント誤差 (Median APE)

- **定義**: 各物件の絶対パーセント誤差 $\dfrac{|y_i - \hat{y}_i|}{y_i}\times 100$ の**中央値**。
- **意味**: 「典型的な（真ん中の）物件で何%ずれるか」。**小さいほど良い**。
- **長所**: 中央値なので**外れ値に最も頑健**。MAPE が悪くても median_ape が良ければ、悪化の主因は一部の難物件と判断できる。
- **読み方**: `mape ≫ median_ape` なら、大半は精度良く当てられているが一部に大ハズレがある状態。

---

## 指標の使い分け早見表

| 指標 | スケール | 単位 | 外れ値への頑健性 | 主な用途 |
|---|---|---|---|---|
| `r2_log` | log | なし | 中 | モデル間の総合比較 |
| `rmse_log` | log | log円 | 低（二乗） | 学習・チューニングの最適化指標（Optuna） |
| `mae_yen` | 円 | 円 | 中 | 「平均で何円ずれるか」の説明 |
| `rmse_yen` | 円 | 円 | 低（二乗） | 大ハズレの検知 |
| `mape` | 円 | % | 低 | 相対精度の総合評価 |
| `median_ape` | 円 | % | 高 | 典型物件の体感精度 |

---

## まとめ: どう読むか

1. **総合性能**は `r2_log` と `rmse_log` でまず把握する（モデル比較・チューニングの主指標）。
2. **実務的な誤差感**は `mae_yen`（円）と `median_ape`（%）で確認する。利用者に説明しやすい。
3. **大ハズレの有無**は `rmse_yen` と `mae_yen` の乖離、`mape` と `median_ape` の乖離で判断する。
   乖離が大きいほど「一部の難物件で大きく外している」サイン。

> **補足**: 本プロジェクトの Optuna チューニングは検証セットの **`rmse_log`（logスケールRMSE）の最小化**を目的関数にしている（`train.py` の `objective()`）。
