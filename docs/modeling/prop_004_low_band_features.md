## 1. 背景と動機

ベースライン（EXP-001）では、価格帯別の Median APE / MAPE が以下のように分布している。

| 帯 | 件数 | Median APE | MAPE |
|---|---:|---:|---:|
| ~2000万 | 1,022 | **17.95%** | **32.08%** |
| 2000万~5000万 | 3,293 | 10.46% | 14.03% |
| 5000万~1億 | 2,438 | 9.09% | 12.29% |
| 1億~3億 | 1,082 | 9.80% | 12.58% |
| 3億~ | 97 | 12.90% | 20.80% |

**低額帯（~2000万）は単体で最悪値**。両端のうち高額帯は PROP-001/002/003 系の介入で扱う方針だが、低額帯はそれらの介入ではほぼ改善しない別問題として残る。

## 2. 低額帯のプロファイル分析

`outputs/test_predictions.csv` から低額帯のみを抽出し、中額帯と比較した結果、低額帯は**極めて明確な単一クラスタ**を形成していることが確認できる。

| 軸 | 低額帯 (~2000万) | 中額帯 (2000万~3億) |
|---|---|---|
| 種類 | **すべて中古マンション** (913/913) | 多様 |
| 構造 | RC 630件 / SRC 240件 / 鉄骨24件（≈97% が鉄筋系） | 多様 |
| 面積中央値 | **25㎡** | 60㎡ |
| 面積 75% 点 | 50㎡ | （未測） |
| 築年数中央値 | **41年** | 21年 |
| 駅距離中央値 | 7分 | 6分 |
| `has_L` | 0（リビング無） | 1 |
| `room_count` | 1 | 2 |

**「築40年超 × 25㎡ × 1K/ワンルーム × RC/SRC 中古マンション」** が低額帯の典型像。
都市計画（用途地域）は住居系396件・商業系339件・工業系166件と分散しており、立地そのものは特殊ではない。

## 3. 既存モデルが外している理由（推定）

EXP-005 のワースト物件 top 3〜5（低額帯への過大予測）:

| 駅 | 実価格 | 予測 | APE |
|---|---:|---:|---:|
| 有明 | 18,000,000 | 181,659,997 | 909% |
| 田町 | 15,000,000 | 152,248,854 | 915% |
| 目白 | 39,000,000 | 194,547,237 | 399% |

これらは**実価格が1,500〜3,900万円**の物件をモデルが**1.5億〜1.9億円**と予測している。

推定メカニズム:
1. 既存特徴量は「築年数」「面積」「駅距離」を個別に扱う
2. LightGBM の木構造は部分的に交互作用を捉えるが、**極端な組合せ**（築40年超 × 25㎡ × 駅近）の非線形効果を十分に学習しきれていない
3. 「築古」「狭小」「ワンルーム」が**同時に成立した時の追加割引**が、それぞれ単独効果の和より大きいはずだが、モデルが過小評価している

→ **明示的な交互作用特徴量を追加すれば改善余地がある**。

ただし、`田町 15,000,000` のような**異常に安い案件**は、観測不能な特殊要因（事故物件・共有持分・定期借地・ペアローン解消等）が原因の可能性が高く、特徴量強化だけでは APE 900% を埋めるのは困難。

## 4. 既存の特徴量（おさらい）

`src/preprocessing/feature_engineering.py` で既に生成されている派生列:

- `log_面積`, `log_最寄駅：距離`, `築年数^2`
- `中心地_距離`, `山手線内側`
- `容積消化率`, `log_建ぺい率`, `log_容積率`, `容積距離`
- `room_count`, `has_L`, `has_D`, `has_K`, `has_S`

単独特徴量と一部の派生は揃っているが、**「築年数 × 面積」「築年数 × 構造」「has_L × 面積」のような明示的交互作用**は欠落している。

---

## 5. 追加候補の特徴量

### 5.1 高優先（低額帯への効きが大きい想定）

| 特徴量名 | 計算式 | 効く理由 |
|---|---|---|
| `築年数×log_面積` | `築年数 * np.log(面積（㎡）)` | 「築古 × 狭小」の相乗的な値下がりを表現 |
| `is_old_studio` | `(築年数 >= 35) & (面積 <= 30) & (has_L == 0)` | 典型的な「築古ワンルーム」フラグ |
| `area_per_room` | `面積 / room_count.clip(lower=1)` | 1部屋あたりの広さ。極小ワンルームを識別 |
| `築年数×構造ダミー` | 構造（RC/SRC/木造/鉄骨）別に `築年数` を分割した4列 | 構造によって築古の効き方が異なる前提 |

### 5.2 中優先

| 特徴量名 | 計算式 | 効く理由 |
|---|---|---|
| `用途×種類` | `categorize_zoning(都市計画) × 種類` の交差カテゴリ | 商業系で住居など特殊組合せを捉える |
| `築年数×駅距離` | `築年数 * 最寄駅：距離（分）` | 古くて駅遠の二重悪条件 |
| `面積バンド` | `面積` を `[~20, ~30, ~50, ~70, 70+]` の5階級に離散化 | 極小・小・中・大の非線形閾値効果 |
| `is_micro_room` | `面積 < 20` のフラグ | 極小物件は単価カーブが急に折れる |

### 5.3 低優先（試す価値はあるが効果限定的）

| 特徴量名 | 計算式 | 効く理由 |
|---|---|---|
| `改装フラグ` | `改装` 列を 0/1 にダミー化 | 既に categorical 化されていれば不要 |
| `has_L × 面積` | `has_L * 面積` | リビング有無の物件規模差 |

## 6. 実装方針

### 6.1 配置場所

`src/preprocessing/feature_engineering.py` の `build_features(df)` 関数内で、既存の派生列追加と同じ流儀で実装する。

例（イメージ。実装時は要検討）:
```python
def build_features(df: pd.DataFrame) -> pd.DataFrame:
    ...
    # 既存
    df["築年数^2"] = df["築年数"] ** 2
    df["log_面積"] = np.log(df["面積（㎡）"].replace(0, np.nan))
    ...

    # PROP-004: 低額帯向け交互作用
    df["築年数×log_面積"] = df["築年数"] * df["log_面積"]
    df["is_old_studio"] = (
        (df["築年数"] >= 35) & (df["面積（㎡）"] <= 30) & (df["has_L"] == 0)
    ).astype(int)
    df["area_per_room"] = df["面積（㎡）"] / df["room_count"].clip(lower=1)
    ...
    return df
```

### 6.2 categorical 列の追加

`categorize_features()` の対象列リスト（`最寄駅：名称`, `建物の構造`, `用途`, ...）に、新規カテゴリ列（`用途×種類` 等）を追加する。

### 6.3 欠損・例外処理

- `面積` が 0 や NaN の場合は `log_面積` が無効化されるため、その伝播先（`築年数×log_面積`）も NaN になる前提で扱う
- `room_count` が 0 の行が混入していないかチェック（0除算回避のため `clip(lower=1)`）
- `築年数` が NaN（未入力）の行への扱いは既存方針に揃える

## 7. 評価方法

### 7.1 採用条件（実験案管理表より）

- 低額帯（~2000万）の **Median APE が 15% 以下**まで縮小
- 中〜高額帯のスコアを悪化させない

### 7.2 追加すると判断しやすい指標

学習ログに**価格帯別 Median APE 表**を出力する（オプション実装）。
これにより「全体平均はやや改善したが、実は中額帯が悪化していた」のような副作用を早期発見できる。

### 7.3 比較対象

- EXP-001（ベースライン）との比較が主軸
- EXP-007（クリップ5億）の R² log 0.928 / Median APE 10.74 とも近い数字が出るはずなので、副次的に比較

## 8. 期待効果と限界

### 効きそうなところ
- 低額帯のクラスタが**極めて明確**（築古×狭小×1K中古マンション）で、交互作用で捉えやすい
- Median APE 17.95% → **20%前後**まで縮小は現実的（−5pp 程度）
- 全体 MAPE は `(1022/7932) × 縮小幅` ≈ **0.5〜1pp** 程度の改善見込み

### 効きにくいところ
- EXP-005 ワースト top の「田町 1,500万」「有明 1,800万」のような**異常に安い物件**は、観測不能な特殊要因が原因。特徴量強化だけでは APE 900% は埋まらない
- 「**MAPE/Median APE 全体が劇的改善**」は期待しない

### 採用条件達成の見通し
低額帯 Median APE を **15% 以下**まで下げるのは結構厳しい目標。PROP-004 単独で達成できるかは不透明で、**PROP-005（後処理での下限制約）と組み合わせ**が必要な可能性がある。

## 9. リスクと留意点

| リスク | 影響度 | 対処 |
|---|---|---|
| 特徴量増加による過学習 | 中 | 4〜10列追加なら影響限定的。Optuna で再探索 |
| 高額帯への悪影響 | 中 | 「築年数×log_面積」は高額にも効く可能性。中〜高額帯の Median APE 悪化を要監視 |
| 多重共線性（既存 `築年数^2` と新規 `築年数×log_面積`） | 低 | LightGBM は耐性あり。解釈時のみ注意 |
| `room_count=0` 等の異常値 | 低 | `clip(lower=1)` で防御 |
| best_params が変わり、過去実験との直接比較が難しくなる | 低 | Optuna 再探索は前提条件として明示 |

## 10. 段階的な進め方（推奨）

**いきなり全特徴量を追加すると、効いた要因の切り分けが難しい**ため、段階分割を推奨。

| ステップ | 内容 | 学べること | 想定 EXP-ID |
|---|---|---|---|
| 1 | 高優先4特徴量だけ追加 | 主要効果の有無 | EXP-XXX |
| 2 | + 中優先特徴量を追加 | 追加効果の有無 | EXP-XXX+1 |
| 3 | 効いた特徴量だけ残して整理 | クリーンな採用版 | EXP-XXX+2（採用候補） |

各ステップで以下を確認:
- 低額帯 Median APE（主要指標）
- 中・高額帯への副作用（特に 1億~3億 帯）
- 全体 MAPE / RMSE / MAE
- best_params の変化
