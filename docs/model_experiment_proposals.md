# モデル実験案管理表

「実施前」の実験案（仮説・改善アイデア）を集約・優先順位付け・状態管理するシート。
実施に移ったら結果は [model_experiment_log.md](model_experiment_log.md) 側に記録する。

両シートの役割分担:

| シート | 何を書くか | 主な目的 |
|---|---|---|
| 本シート（実験「案」） | 未実施の案・仮説・期待効果・優先度・状態 | 何をやるか／やらないかの判断材料 |
| 実験ログ（[model_experiment_log.md](model_experiment_log.md)） | 実施済の介入・スコア・観察・次の手 | 結果と学びの蓄積 |

---

## 1. 運用ルール

### 案IDの付け方
- 実験案には `PROP-XXX` を採番（連番。欠番は埋め直さない）
- 実施に移ったら `model_experiment_log.md` 側で `EXP-YYY` を採番し、本シートの「紐EXP」欄にリンクする
- 実施案は本シートから削除せず、状態を「Done」または「Rejected」に変えて履歴を残す

### 状態（Status）
- **Proposed**: 起票直後。中身を煮詰める段階
- **Approved**: 仮説・介入・評価基準が固まり、実施待ち
- **In Progress**: 実装中／学習中
- **Done**: 実施完了。結果は `EXP-YYY` を参照
- **Rejected**: 実施したが採用しない／実施する価値が低いと判断して見送り
- **Deferred**: 一旦保留（後続案の結果待ち、優先度低など）

### 優先度の決め方
**期待効果 × 実装コスト** の2軸で評価する。

| 優先度 | 目安 |
|---|---|
| High | 期待効果大かつ実装コスト小〜中。直ちに実施したい |
| Medium | 期待効果中、または効果大でもコスト高 |
| Low | 期待効果小、もしくは前提条件（別案の完了など）が必要 |

### 起票の必須事項
新規案を起こす際は最低限以下を埋める:
- 一言要約
- 仮説（何が良くなることを期待するか）
- 介入内容（どのファイル・パラメータ・処理を変えるか）
- 期待効果（どの指標がどれくらい動く想定か）
- 評価基準（採用／不採用の判断軸）
- リスク（うまくいかない可能性・副作用）

## 3. 個別案詳細

### PROP-001: Huber 損失への切替

| 項目 | 内容 |
|---|---|
| 状態 | Approved |
| 優先度 | High |
| 起票日 / 起票者 | 2026-06-01 / — |

**仮説**
- 現状の objective は MSE（L2）相当で、二乗ペナルティのため高額物件の誤差がモデル学習を強く引っ張っている
- Huber 損失は閾値 `alpha` 以下は L2、超は L1 で線形ペナルティに切り替わるため、外れ値の影響を**サンプルを消さずに**抑えられる
- EXP-005 で「サンプルを消す方向」は逆効果と確認済み。Huber は反対方向の正攻法

**介入内容**
- `LGBMRegressor(objective='huber', alpha=...)` に切替
- `configs/model_params.yaml` の固定パラメータに `objective: huber` を追加
- `lgbm_search_space` に `alpha` の探索範囲（例: 0.5〜2.0、log=True）を追加
- 探索コストが増えるため `n_trials` の調整も検討

**期待効果**
- MAE/RMSE 円スケールが EXP-001 比で改善（特に RMSE）
- R² log・RMSE log・MAPE・Median APE はほぼ維持

**評価基準（採用条件）**
- MAE と RMSE がともに EXP-001 比で改善（≥ 5%）
- かつ R² log が 0.92 以上、Median APE が 11% 以下を維持

**リスク**
- `alpha` の選定が外れるとロバスト性が出ず、log 系も悪化する
- 既存ハイパーパラメータと組み合わせて再探索が必要

**関連実験**
- 反対方向の失敗例として EXP-005 を参照
- 次の優先案 PROP-002 と効果が独立に出るかの比較に使える

### PROP-002: サンプル重み付け（価格帯均等化）

| 項目 | 内容 |
|---|---|
| 状態 | **In Progress** |
| 優先度 | High |
| 起票日 | 2026-06-01 |
| 紐EXP | EXP-006（予定） |

**仮説**
- 高額物件は件数が少ない一方で誤差絶対量が大きく、平均誤差を引っ張る
- 学習時の `sample_weight` を価格帯別に調整すれば、サンプルを残したまま影響度のみコントロールできる

**介入内容**
- 案A: `1 / log(price)` のような連続重みで高額側を逓減
- 案B: 価格帯ごとに固定重みを与え、件数差を均す
- LightGBM の `fit(X, y, sample_weight=...)` 引数に渡す
- Optuna の探索対象に重み付けスキームのスイッチや係数を含めるかは要検討

**期待効果**
- 全体の MAE/RMSE の改善
- 価格帯別 Median APE のばらつき低下（特に低額帯が単独で悪化しないことを確認）

**評価基準**
- MAE/RMSE が EXP-001 比で改善（≥ 3%）
- 価格帯別 Median APE の最悪値が縮小

**リスク**
- 重み設計の自由度が大きく、Optuna の探索負荷が増える
- 過学習傾向が出やすい

**関連実験**
- PROP-001（Huber）と効果が排他的でないため、両方試して比較する価値あり

### PROP-003: クリップ閾値の緩和（5億 / 10億）

| 項目 | 内容 |
|---|---|
| 状態 | Proposed |
| 優先度 | Medium |
| 起票日 | 2026-06-01 |

**仮説**
- EXP-005 の3億クリップは除外件数が train 256件と多すぎ、高額帯の予測能力を喪失した
- 閾値を5億・10億まで緩めれば除外件数は数十件以下に減り、外れ値抑制と学習維持の両立余地がある

**介入内容**
- `train.py` の `_TRAIN_PRICE_CAP_YEN` を 5e8 / 1e9 にして再学習
- それぞれ別実験（EXP-XXX）として記録

**期待効果**
- MAE/RMSE が EXP-001 と同等以上、可能なら微改善

**評価基準**
- EXP-001 を下回らないこと
- 下回るなら不採用、上回るなら閾値を最適化する候補に昇格

**リスク**
- 中途半端な閾値だと EXP-005 のように悪化する
- PROP-001/002 と比べると効果の天井が低い可能性

**関連実験**
- EXP-005（3億クリップ）を参照

### PROP-004: 低額帯（~2000万）の特徴量強化

| 項目 | 内容 |
|---|---|
| 状態 | Proposed |
| 優先度 | Medium |
| 起票日 | 2026-06-01 |

**仮説**
- ~2000万帯の Median APE 17.95% / MAPE 32.08% は単体で最悪値
- 既存の特徴量だけでは低額物件の価格決定要因（築古・狭小・駅遠・用途地域差）を捉えきれていない
- 交互作用特徴量を増やせば説明力が上がる

**介入内容**
- `src/preprocessing/feature_engineering.py` に追加候補:
  - `築年数 × 構造`（築古RC vs 築古木造の差を表現）
  - `駅遠 × 面積`（駅遠×広い → 安い、駅近×狭い → 高単価）
  - 用途地域の細分類（商業系/住居系のサブクラス）
  - `area_per_room` のような派生

**期待効果**
- 低額帯の Median APE / MAPE 改善
- 全体 MAPE もわずかに改善

**評価基準**
- 低額帯（~2000万）の Median APE が 15% 以下まで縮小
- 中〜高額帯のスコアを悪化させない

**リスク**
- 特徴量増加で過学習リスク
- 高額帯への悪影響の可能性

### PROP-005: 低額帯への過大予測の下限制約

| 項目 | 内容 |
|---|---|
| 状態 | Proposed |
| 優先度 | Low |
| 起票日 | 2026-06-01 |

**仮説**
- EXP-005 のワースト物件 top 3-5 は「実価格 1,500〜3,900万」を「予測 1.5〜1.9億」とした桁違いの過大予測
- 後処理で「物件特徴量から見て妥当な範囲」に予測値をクリップすれば APE が大幅改善

**介入内容**
- 推論後、`予測価格 ≤ 面積 × 想定単価上限 × バッファ` のように頭打ち
- 想定単価は地域・物件種類別に表を持つ

**期待効果**
- ワースト級の極端な誤予測を抑制し、MAPE 改善

**評価基準**
- ワースト物件 top 5 の APE が大幅に縮小
- 通常物件の予測に影響しない

**リスク**
- 一律ルールが現実的に難しい（地域差・希少物件への副作用）
- モデルの問題を後処理で隠す形になり、根本解決にならない

**関連案**
- PROP-004（低額帯特徴量強化）を先に試し、それでも残るなら本案を検討

### PROP-006: 価格帯2分割アンサンブル

| 項目 | 内容 |
|---|---|
| 状態 | Deferred |
| 優先度 | Low |
| 起票日 | 2026-06-01 |

**仮説**
- 低額帯と中〜高帯では価格決定要因が異なる（低額: 物理条件、高額: ブランド/眺望）
- 専用モデルで分けた方が両帯の精度が上がる可能性

**介入内容**
- ~2000万専用モデル + その他メインモデル
- 推論時は分類器（または特徴量ルールベース）で振り分け
- 学習・推論・評価パイプラインの大改修

**期待効果**
- 全帯の MAPE 改善

**評価基準**
- 全帯の Median APE が単一モデル比で改善
- 運用負荷増を上回る効果が出ること

**リスク**
- 実装・運用コストが大きい（モデル2つ、分類器1つ）
- 境界の不連続
- 高額帯の専用化は test 件数が少なすぎて不安定

**関連案**
- PROP-001/002/004 で改善余地が尽きた後の最後の手段として保留

## 4. アーカイブ（Done / Rejected）

### PROP-A1: 学習側のみクリップ（3億）→ Rejected

| 項目 | 内容 |
|---|---|
| 状態 | **Rejected** |
| 紐EXP | EXP-005（2026-06-01 実施） |
| 起票日 | 2026-06-01 |

**仮説（当時）**
- 高額外れ値を学習データから除外すれば、MAE/RMSE が改善する

**結果**
- EXP-005 で全指標がベースライン（EXP-001）を下回り、特に RMSE が +28.9% と大幅悪化
- 原因: 学習データから3億超を除いた結果、test に残る高額物件への予測能力を喪失

**学び**
- 「サンプルを消す」方向は逆効果。**サンプルを残しつつ影響を抑える**方向（PROP-001/002）へ転換
- クリップを使うなら閾値を緩める（PROP-003）か、後処理（PROP-005）に限定

## 6. 案サマリの運用例

新しい案を思い付いたら:
1. §5 のテンプレートをコピーして §3 に貼り、内容を埋める
2. §2 のサマリ表に1行追加（起票日・優先度・状態=Proposed）
3. レビューで Approved になったら状態を更新
4. 実施に着手したら状態を In Progress、`model_experiment_log.md` に EXP-YYY を起こす
5. 実施完了後、本シートの状態を Done または Rejected に変え、「紐EXP」欄にリンクを記入
