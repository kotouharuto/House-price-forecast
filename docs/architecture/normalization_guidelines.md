# 特徴量の正規化ガイドライン

東京都賃貸物件の賃料予測プロジェクトで扱う特徴量について、**正規化（対数変換 / 標準化）の必要性と推奨対象**をまとめる。

## 基本方針

- 主モデルは **LightGBM / XGBoost**（木ベース）
- 木ベースモデルは数値特徴量のスケーリング（標準化等）に **基本不要**
- ただし、以下のケースでは正規化が有効：
  - 目的変数（賃料）が大きく歪んでいる → **対数変換**
  - 線形回帰・ニューラルネット・k-NN を比較評価する → **標準化**
  - SHAP の解釈性向上、可視化のスケール統一 → 任意で標準化

---

## 1. 対数変換 (`np.log1p`) を推奨

歪度（skew）が大きく、log変換でモデル性能・可視化品質が改善する可能性が高い列。

| 列名 | skew | 優先度 | 備考 |
|---|---|---|---|
| `取引価格（総額）` | **86.52** | 🥇 必須 | 目的変数なら対数変換は定石。**外れ値処理と併用** |
| `面積（㎡）` | 1.24 | 🥈 推奨 | 広い物件への偏りを是正 |
| `最寄駅：距離（分）` | 1.05 | 🥉 任意 | 軽度だが効果あり |
| `容積率（％）` | 0.64 | 🥉 任意 | 商業地で値が跳ねる |

### 実装例

```python
import numpy as np

# 目的変数の対数変換（学習時）
y_log = np.log1p(df["取引価格（総額）"])
model.fit(X, y_log)

# 予測後に元のスケールへ戻す
y_pred = np.expm1(model.predict(X_test))

# 特徴量側の対数変換
df["log_面積"] = np.log1p(df["面積（㎡）"])
df["log_距離"] = np.log1p(df["最寄駅：距離（分）"])
```

---

## 2. 標準化 (`StandardScaler`) を検討

**LightGBM では不要**。線形回帰・NN・k-NN 等を比較する際にのみ適用する。

| 列名 | レンジ | スケール感 |
|---|---|---|
| `面積（㎡）` | 10〜640 | バラつき大 |
| `築年数` | -1〜72 | 中程度 |
| `最寄駅：距離（分）` | 0〜29 | 中程度 |
| `建ぺい率（％）` | 30〜80 | 中程度 |
| `容積率（％）` | 60〜1000 | バラつき大 |
| `最寄駅：緯度` | 35.51〜35.81 | 狭い |
| `最寄駅：経度` | 139.26〜139.90 | 狭い |

### 実装例

```python
from sklearn.preprocessing import StandardScaler

num_cols = [
    "面積（㎡）", "築年数", "最寄駅：距離（分）",
    "建ぺい率（％）", "容積率（％）",
    "最寄駅：緯度", "最寄駅：経度",
]
scaler = StandardScaler()
df[num_cols] = scaler.fit_transform(df[num_cols])
```

> **注意**: スケーラは `fit` を**訓練データのみ**で行い、検証・テストデータには `transform` のみ適用する。リークを防ぐため。

## 3. 正規化不要

| 列名 | 理由 |
|---|---|
| `価格情報区分` | 0/1 のバイナリ |
| `has_L`, `has_D`, `has_K`, `has_S` | 0/1 のバイナリ |
| `room_count` | 1〜6 の離散値 |
| `取引四半期` | 1〜4 の離散値 |
| `改装` | 0/1 のバイナリ |
| カテゴリ列全般（`種類`, `用途`, `今後の利用目的`, `都市計画`, `建物の構造`, `住所`, `最寄駅：名称`） | LightGBM が `category` 型を直接扱える |

---

## 4. 既知の注意点（要対処）

| 項目 | 内容 | 対処方針 |
|---|---|---|
| `取引価格（総額）` の外れ値 | **max=160億円** （事業用物件の混入が疑われる） | 賃料予測対象に絞った後、上下1%でクリップ or IQR法で除外 |
| `築年数` に **-1** | 建築年が未来の前売り物件（2027年建築予定など） | 設計上は許容、ただし学習時に上限・下限フィルタ検討 |
| `最寄駅：緯度／経度` に 871件の欠損 | 駅マスタにない私鉄駅や `Unknown` | LightGBM の NaN ハンドリングに任せる（A方針） |
| `改装` に 27,857件の欠損 | 元データで未記入の物件 | 「欠損 = 未改装」として 0 で埋めるか別フラグ列で表現 |

---

## 5. 適用順序の推奨

```
1. clean_data        : 欠損値補完・型変換
2. build_features    : カテゴリ化・特徴量抽出
3. 外れ値処理        : 取引価格などの上下クリップ
4. 対数変換          : log_面積, log_距離, log_賃料 (目的変数)
5. （任意）標準化    : 線形モデル比較時のみ
6. train/test split  : 学習用データに分割
7. モデル学習        : LightGBM 等
```

---

## 参考: モデル別の正規化の必要性

| モデル | 対数変換 | 標準化 |
|---|---|---|
| **LightGBM / XGBoost** | 目的変数のみ推奨 | 不要 |
| 線形回帰・Ridge・Lasso | 目的変数・特徴量とも推奨 | 必要 |
| k-NN | 目的変数推奨 | 必要 |
| ニューラルネット | 目的変数推奨 | 必要 |
| ランダムフォレスト | 目的変数のみ推奨 | 不要 |
