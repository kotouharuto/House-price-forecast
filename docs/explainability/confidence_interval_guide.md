# 信頼区間ガイド（Quantile Regression）

不動産 AVM の予測区間（Phase 2 で導入）の出力をどう読むかをまとめたガイド。
学習ログ（`logs/train_quantile.log`）の各行を解釈し、モデルが業務利用に耐える
キャリブレーションになっているか判定するための文書。

- ロードマップ: [roadmap.md](roadmap.md) §Phase 2
- 関連: [whatif_analysis_guide.md](whatif_analysis_guide.md) / [../modeling/evaluation_metrics.md](../modeling/evaluation_metrics.md)

---

## 1. 信頼区間とは何か

点推定だけでなく、予測値の**幅**を返すこと。Quantile Regression では分位点 α を変えた
3 つのモデル（low / median / high）を別々に学習し、予測時に区間として返す。

```
予測価格: 5,200 万円
  90% 信頼区間: 4,700 万円 〜 5,800 万円
```

### 名目カバレッジ vs 実カバレッジ

| 用語 | 意味 | 例 |
|---|---|---|
| **名目カバレッジ** | 設計上の信頼区間幅。`upper_alpha − lower_alpha` | α=0.05 と 0.95 → 名目 90% |
| **実カバレッジ** | テストセットで実価格が `[lower, upper]` に入った割合 | 78.94% など |

理想は **名目 ≈ 実**。乖離が大きいと「90% と言ったのに 79% しか当たらない」となり、AVM の信頼性が崩れる。

### 不動産 AVM での意味

- **業務リスク管理**: 銀行融資判断で「自動承認 / 人手査定」の境界を区間幅で決める
- **顧客説得力**: 「断定しない誠実さ」を価格提示で示せる
- **異常物件検出**: 区間が極端に広い物件 = 学習データ分布外、人手査定推奨フラグ

## 2. ログファイルの読み方

[logs/train_quantile.log](../../logs/train_quantile.log) を確認する。

### 1 行の構造

```
2026-06-14 22:53:45 | INFO    | __main__ | カバレッジ率: 名目 90% / 実測 78.94% (差分 -11.06pp)
└─ 日時 ──┘   └─ レベル ─┘  └─ モジュール ─┘  └─ メッセージ ───────────────────────┘
```

| 部分 | 意味 |
|---|---|
| 日時 | 出力時刻 |
| レベル | `INFO` / `WARNING` / `ERROR` |
| モジュール | `__main__` = 本番実行 / `src.modeling.train_quantile` = pytest 経由 |
| メッセージ | ログ本文 |

### 1 回の本番学習で出力される行（順序）

1. 学習設定（α リスト・overrides）
2. α=0.05 のモデル学習完了
3. α=0.50 のモデル学習完了
4. α=0.95 のモデル学習完了
5. モデル保存パス（low）
6. モデル保存パス（med）
7. モデル保存パス（high）
8. **カバレッジ率**（最重要）
9. **区間幅**
10. 学習完了 + 所要時間

## 3. カバレッジ率の判定基準

### 計算式

```
名目カバレッジ = upper_alpha − lower_alpha       (例: 0.95 − 0.05 = 0.90)
実カバレッジ   = mean(lower ≤ y_true ≤ upper)     (テストセットでの平均)
差分           = 実カバレッジ − 名目カバレッジ    (単位: パーセンテージポイント [pp])
```

### 状態判定表

| 差分 | 状態 | 改善方針 |
|---|---|---|
| `0 ± 5pp` | キャリブレーション良好 | OK。次のフェーズに進む |
| `−5 〜 −15pp` | やや過信（区間が狭い） | α 拡張 / `min_child_samples` を上げる |
| `< −15pp` | 過信ひどい | 目的変数の log 変換見直し・モデル設計再考 |
| `+5 〜 +15pp` | やや過小評価（区間広い） | 実用上は許容範囲 |
| `> +15pp` | 過小評価ひどい | α 縮小。広すぎて使えない |

### 現状（2026-06-14 時点）

- 名目 90% / 実測 78.94% / **差分 −11.06pp**
- → **やや過信**。Phase 5 で価格帯別分析を行い、α 拡張・ハイパラ調整を検討

## 4. 区間幅の読み方

```
区間幅（円）: 中央値 20,073,633 / 平均 34,026,403
```

### 中央値 vs 平均

| 指標 | 解釈 | 注意 |
|---|---|---|
| 中央値 | 「半数の物件が、この幅より狭い区間を持つ」 | 外れ値に頑健。日常運用の感覚値 |
| 平均 | 外れ値の影響を受ける | 高額物件で広い区間が出ると引き上げられる |

### 平均 >> 中央値 のとき

**高額物件で区間が大きく広がっている**ことを示す。例: 中央値 2,000 万・平均 3,400 万 →
高額帯の予測が不安定。Phase 5 で価格帯別に PIAW（Prediction Interval Average Width）を
分解して確認する。

### 区間幅の目安（不動産 AVM の感覚）

| 区間幅 / 予測値 | 評価 |
|---|---|
| `< 10%` | 狭すぎる。過信の可能性大 |
| `10〜30%` | 標準的 |
| `30〜50%` | 広め。低信頼物件として扱う |
| `> 50%` | 広すぎ。人手査定推奨フラグ |

## 5. pytest 由来ログとの混在に注意

`logs/train_quantile.log` は本番実行と pytest 実行の**両方**が混ざる。

### 見分け方

| モジュール部分 | 由来 |
|---|---|
| `__main__` | 本番（`uv run python -m src.modeling.train_quantile`） |
| `src.modeling.train_quantile` | pytest 経由（テストで関数が呼び出された） |

### pytest 由来の数値は本番評価ではない

```
INFO | src.modeling.train_quantile | カバレッジ率: 名目 80% / 実測 84.67% (差分 +4.67pp)
INFO | src.modeling.train_quantile | 区間幅（円）: 中央値 3 / 平均 7
```

区間幅が「3 円」のような不自然な値は、テストの合成データを使った評価のため。
**本番のカバレッジ確認には使わない**。

### 本番ログだけ抽出

```bash
grep "__main__" logs/train_quantile.log | grep -E "カバレッジ|区間幅|所要時間"
```

これで時系列に本番学習結果だけ並ぶ。ハイパラ変更の前後比較に使う。

## 6. 改善のアプローチ

カバレッジ率が目標（85〜95%）から外れたときの順序:

### Step 1: α の調整

| 目的 | 変更 |
|---|---|
| 区間を広げる | α を端に寄せる: `[0.025, 0.50, 0.975]`（95% 区間） |
| 区間を狭める | α を中央に寄せる: `[0.10, 0.50, 0.90]`（80% 区間） |

`configs/model_params.yaml` の `quantile.alphas` を変更し、再学習。

### Step 2: LightGBM ハイパラの調整

- `num_leaves` を下げる: モデル複雑度を抑えると過信が緩む
- `min_child_samples` を上げる: 葉ごとの最小サンプル数を増やすと外挿が安定
- `n_estimators` を下げる + `learning_rate` を上げる: 学習を浅くする

### Step 3: 価格帯別分析（Phase 5）

「全体カバレッジは良いが、低額帯だけ大きく外れる」というケースが多い。
Phase 5 で `src/visualization/aggregate.py` に `coverage_rate_by_band()` を追加し、
価格帯ごとの内訳を BI ダッシュボードで可視化する。

### Step 4: Conformal Prediction（最終手段）

Quantile Regression でカバレッジ保証が出せない場合、Conformal Prediction で
**理論的にカバレッジを保証**する。`mapie` ライブラリで実装可能。
ただし区間が広めに出る傾向があり、実用性とのトレードオフ。

## 7. よくある誤解

### 誤解 1: 「実カバレッジ 100% にすればいい」

→ 違う。100% にしようとすると区間が広くなりすぎて実用性が消える。
   名目に近い実カバレッジが**良いキャリブレーション**。

### 誤解 2: 「中央値モデル（α=0.50）は通常モデルと同じ」

→ 違う。`objective="quantile"` で α=0.50 を学習すると、損失関数が
   **Mean Absolute Error** に等しくなる（Median 回帰）。一方、通常の
   `lgbm_model.pkl` は `objective="huber"` で学習しているため、点推定の精度は
   既存モデルの方が良いことが多い。**点推定は既存モデル、区間は Quantile モデル**と
   役割分担するのが正解。

### 誤解 3: 「区間が広いほどモデルが慎重で良い」

→ 違う。区間が広すぎる = 使い物にならない予測。「3,000 万円 〜 8,000 万円」と
   言われても顧客は何も決められない。**狭くて、かつ実際に当たる**区間が理想。
